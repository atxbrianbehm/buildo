## Queue and failure handling
A settled capture-result promise and FIFO tail are reserved before capture or retention callbacks. Both capture fulfillment and rejection handlers are attached immediately, so an out-of-order failure cannot orphan a rejection behind older IO. The job awaits capture even when retention failed; actual capture failure takes priority. P8 record creation and writer put execute only in accepted sequence. Each caught failure advances the queue. The drain method returns the tail existing at call time; later accepted jobs do not extend that returned promise.

The optional synchronous retainer must provide an already-held exclusive capability for the exact document, with put and release. Undefined, nonexclusive, wrong-document or throwing retention yields a typed unsaved failure and zero puts. Every obtained callable release is wrapped once and executed in job finally. A release error cannot replace capture/put failure or downgrade an acknowledged saved write. This is a trusted injection contract, not actual browser lock acquisition or cross-tab CAS. No default App writer/factory is added.

Explicit imports take priority over any source on an injected restore adapter and create the bounded source-unavailable marker.
