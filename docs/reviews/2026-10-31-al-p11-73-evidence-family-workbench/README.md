# AL.P11.73: Evidence-linked grouped families in the workbench

When a signed, awning-bearing source building has an applied interpretation, its grouped-family preview carries that source record. The family inspector reports whether the selected member's opening-head setting matches or differs from the source; it explicitly says that this comparison does not verify the claim for the member. Saving the family embeds the full staged extract. The source claim remains unreviewed.

Linked grouped-family files can be saved and reopened independently of the current source building. Individual awning-fabric edits preserve the record and recompute the family wrapper. Invalid linked files leave the existing preview in place. Regular unlinked grouped-family files keep their existing formats and workflow. Other family formats do not yet retain the record; the workbench still asks artists to save the linked source building separately for those formats. This does not establish a live UTDG integration, historical coverage, or street readiness.

The synthetic browser workflow creates the signed source, applies an interpretation, previews and saves a family with fabric variation, checks all six member labels, edits a member's fabric, opens an unlinked source, reopens the linked family, rejects a corrupted file and returns to the unlinked source. It then opens an older unlinked family and verifies no source interpretation leaks into it. It checks no material-provider calls and captures the actual preview and phone label. Run `node docs/reviews/2026-10-31-al-p11-73-evidence-family-workbench/verify.mjs webgl <new-output-dir>` or `webgpu`; append `plain` to start without fabric variation and then add an override. The previous unlinked grouped-arch workflow is checked separately. Captures are in the Buildo phone gallery; the family still has repetitive façades.

Validation passed: typecheck, lint, production build, focused UI tests, full suite with two workers (2,156 tests in 191 files), standard browser smoke, WebGL and WebGPU linked-family workflows, the plain-to-fabric transition, the prior unlinked grouped-arch workflow and the Impeccable detector. Two workers were used because an existing family-edit wait had timed out under default concurrency in earlier runs. The build retains its existing chunk-size warning.
