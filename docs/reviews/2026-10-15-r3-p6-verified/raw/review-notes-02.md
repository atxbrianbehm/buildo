# R3.P6 source, UI and browser-workflow review

Root reviewed the six bounded paths against accepted P5 preimages. Independent lanes reviewed the three production UI paths and the browser harness, with no remaining blocker. Core/compiler, saved-source/controller, renderer, material and all other 247 source files remain literal.

AssemblyHall reports a selection only from its current attached viewer and the existing exact native-window resolver. Pointer, keyboard, reveal and attachment share this path. The event carries the actual fixture and canonical semantic path; metadata does not invent a selected target. Candidate preparation remains inert. Commit can temporarily report a candidate, but rollback reattaches and reports the previous owner. Old viewer retirement cannot clear a newer selection. A callback ref avoids making callback identity a renderer-remount dependency; cleanup still attempts owned resources if a callback throws.

App keeps the raw Hall event until the accepted artifact catches up after viewer commit. Its model binds that event to exact fixture/source references, source hash, revision, document and semantic address. Each asynchronous split read owns its source, has a separate read token and checks room, owner and authority before publishing the model. Original dimensions come from the authoritative unedited split and the accepted catalog/profile; replacement width comes from source v4, never inverse Float32 transforms.

The visible inspector uses the existing workspace design, a native labelled numeric field in metres, explicit Apply and Restore original, the original ceiling and 0.23 m minimum. Empty/nonfinite/out-of-range drafts and unchanged Apply are blocked. Source-unavailable views explain portable Open. A dirty global draft blocks local edits rather than allowing the local transaction to consume unpublished global changes. A synchronous subscription also cancels local preflight if a global draft becomes dirty while it is pending.

An action claims its pending lock before controller preflight, binds source hash/revision/address and delegates to the protected P5 transaction. Duplicate clicks are inert. Cancel, Run, Open, Import, document change and unmount invalidate older intent. Room departure clears selection and cancels pending local work. Completion releases its own lock even if selection changed; it does not overwrite a newer draft. Successful attachment supplies the replacement model/outline. The store subscription clears the pending ref before cancelling, avoiding recursive cancellation.

Four Hall and six App cases extend existing coverage. The App cases use the actual controller, fixture and Hall selection seam with a fake renderer, and cover Apply/Restore/Save/Open, exact materials/IR, invalid drafts, dirty global state, stale reads, pending cancellation/duplication, selection/document/Open/unmount races and source-unavailable recovery. Historical test and hook calls and helper declarations remain literal; the structural source review checks their ordered AST call bodies rather than requiring a growing outer describe wrapper to remain byte-identical.

The real browser harness retains every prior assertion and schema. New instrumentation is installed after each App is ready and before tested actions. It observes actual controller/provider/interpreter methods, IndexedDB writes and actual submitted native frame/glass meshes through onBeforeRender. Full owned records preserve own property names/flags/prototypes, undefined, negative zero, array length, typed view kind/offset/backing length and every raw byte. Source files are decoded through the actual codec. Narrowing, replacement/increase, fresh-page explicit portable Open and Restore compare complete source/IR/gallery/pinned inputs and all five material channels plus full metadata. Native selected matrix local-X ratios use the independent binder equation; other components and all unselected matrices remain exact.

The first browser attempt passed the old workflow plus selected/narrowed/increased, then failed because an implicit browser.newPage context forbade a second page. All six candidate sources and the failed log were captured before repair. Only the harness changed: explicit default context/newPage and normal context close. All other 252 sources, including the three UI paths and both tests, remain literal. Wrapper helpers also retain their failed preparation attempts: one transcribed digest had a duplicate character; another exact-diff expectation incorrectly assumed CRLF. The corrected recorder derives the original line endings and validates stored file pins without transcription. These recorder failures changed no feature source.

Hook installation/restore is guarded, wrappers restore in reverse order, readonly database handles close in finally and both pages/context/browser clean up on success or failure. No production-owned fixture/material resources are disposed by the probe. Browser counters exclude startup explicitly. Nonempty width edits and fresh portable Open do not write completed cache; restoring an empty list may write one compatible completed packet while retaining prior records.

Limitations remain explicit: the fresh page uses portable Open, not automatic restart recovery; edited completed-cache replay, undo, wider target lists and CompilerClient App wiring remain separate work. Four portable legacy canaries and their P5 runtime roundtrips are inherited with literal codec/core and pinned files, not rerun as a new four-canary claim. Root inspects desktop/compact captures for the new controls, not human building appearance acceptance or representative-machine performance.
