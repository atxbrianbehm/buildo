# R3.P10 source and lease-lifetime review

Scope is exactly two new paths: buildingSourceCheckpointWriter and its test. The frozen 255 existing sources remain literal, including App, controller, P8 persistence, portable codec, compiler, material and renderer code. P9 capability is imported as a type only. No existing serializable contract changes. Executed check outcomes belong to the separately pinned logs.

## Acquisition and ownership
Options are trusted ports, read synchronously once before asynchronous work. The exact nonempty document string, lock manager/request method and persistence factory references are captured. The lock name is the fixed prefix plus JSON.stringify(documentId), which preserves exact identity and avoids delimiter and lone-surrogate encoding collisions. Native request is exclusive with ifAvailable:true and no signal, steal, queue or timer. Unsupported/missing callable request and null grant return undefined without storage construction.

Only an exact name/exclusive-mode grant constructs persistence, snapshots its callable put and makes a frozen session. Acquisition failure wraps the original native/factory cause in the existing WriteFailed error. Callback, request and ready outcomes have immediate handlers; a synchronous request callback or throw is contained. The callback stays pending on a resolve-only quiescence promise. The native request outcome is handled independently, so close waits for actual native settlement instead of assuming callback completion equals settlement.

## Retention, admitted calls and acknowledgement
Matching-document retain is synchronous and requires held ownership and an open root. Closing immediately forbids new retains, caches its promise and attaches a rejection observer without consuming the returned failure. Existing retained capabilities remain usable until release. Release is once-only and only blocks later calls. An admitted put increments active work before invoking the actual P8 parser, whose synchronous prefix owns finite JSON and validates descriptors before await; caller data is neither frozen nor reread after mutation.

Active work covers the whole parse/validation/delegation/acknowledgement pipeline, not merely the final storage await. A released capability cannot admit another IO. Already admitted work stays counted even after early capability release or root close. The callback resolves only after root close, zero retained references and zero admitted pipelines. After parsing, exact document and held state are checked before delegation. P8 Invalid errors propagate unchanged; wrong-document/state and IO failures use WriteFailed with the exact cause. The real P8 storage wrapper supplies transaction-complete acknowledgement.

Unexpected request settlement before local quiescence marks ownership lost immediately. Future retains/calls/delegation fail closed. If loss is observed after IO was delegated, its eventual acknowledgement is conservatively reported failed with the native cause; that IO may already have committed. There is no rollback claim. Close still drains admitted work and references before returning the native failure.

## Causal tests and review
Root read all eight initial cases and the controlled manager/storage helpers. The manager implements installed generic request overloads and separates callback completion from native request settlement. Causal coverage includes deferred factory, same-document contention versus independent documents, unsupported/native/factory failures, captured option getters, root close before retained work, repeated release/close, and close pending after callback completion until native settlement.

Actual P8 parser and persistence are used with source-unavailable marker records. A spy preserves the real synchronous ownership prefix and delays only continuation. Caller mutation then proves the parsed/committed record remains exact and unfrozen caller objects remain mutable. Early release while parsing and IO are independently held cannot unlock work. Invalid hash and accessor rejection preserve actual parser failure and invoke no getter/IO; foreign and released calls cannot write, while a still-held root can retain a replacement capability. Actual P8 storage failure retains its nested exact cause, leaves the session held and permits a later successful write.

Native loss is tested separately during held parse and after delegated IO. New work is denied, close stays pending while old work drains, pre-delegation loss performs no put, and post-delegation loss reports uncertainty despite the controlled commit. Cleanup releases all capabilities and settles native requests, with no orphaned promise. These tests prove the capability seam with a controlled manager; real browser cross-tab integration belongs to App activation.

## Acquisition-delivery review repair
Independent review found that a native failure queued around grant delivery could be observed before acquisition returns while the readiness promise already carried an acquired session. The candidate's two new sources and all257 manifest were captured before repair. The bounded fix yields one acquired-path microtask, rechecks held/native-settlement state and closes/quiesces before rejecting with the existing loss cause. This prevents returning a dead session for an already-settled request, without claiming protection from a future native failure after delivery.

A ninth causal case covers synchronous grant followed by already-rejected native return, and asynchronous grant plus rejection in the same turn. No IO occurs and callback quiescence is reached after rejected acquisition. The original eight test bodies remain literal. Final source and all checks are recorded after this review repair; the candidate was never check-tested.

## Scope and limits
The module allocates promises and small per-session state, no listeners, timers, GPU assets, scene objects or provider work. Structural/material decisions are unchanged and no Math.random is added. P9 remains the publication FIFO; this module adds no CAS, restore, startup, new database schema, undo or App defaults. P7 transaction completion is acknowledgement rather than an explicit physical-disk flush guarantee.

Existing browser workflows rerun separately on unchanged App behavior. P6 inspected desktop/compact captures and emitted-runtime equivalence, plus P5 portable canary roundtrips, remain explicitly inherited. No new screenshot/detector pass, automatic restart recovery, appearance approval, representative-machine performance or release readiness is claimed.
