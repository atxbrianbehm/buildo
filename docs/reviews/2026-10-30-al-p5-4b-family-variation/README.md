# AL.P5.4b: seeded grouped-window family variation

The Related buildings controls now include an opt-in for grouped upper windows. Composition plan 0.2 records the seeded demo choices; family source 0.4 stores that plan and the actual editable member graphs. Prior version-one compositions and family sources remain readable. Each member can retain single openings or add a pair or triple to an available front upper bay. Width is derived from the generated bay and stored in the member graph. Existing authored groups and local width targets remain intact; no available bay, an opening lock or an incompatible rounded source fails explicitly. When head variation is also enabled, members assigned round heads keep a single opening at the added location because grouped arches are not yet implemented.

Both [WebGPU](webgpu-01/receipt.json) and [WebGL](webgl-02/receipt.json) used the actual app to generate a family with all four variation groups selected, edit one paired member, save and reopen the family. This seed produced group counts `2, 0, 2, 0, 3, 0`; round-headed members had no added group. The workflow checked the actual saved choices, unchanged source and siblings after the edit, matching shared material source and zero additional material-provider calls. [WebGPU family](webgpu-01/family.png), [WebGL family](webgl-02/family.png) and [edited member](webgpu-01/member.png) are actual textured captures. [Workflow](verify.mjs) explicitly generates a fresh demo source with edited assemblies released, then re-enables preservation for the family.

The first exploratory attempt used an older project containing an authored opening-width lock and was rejected by the lock check; it is excluded from the successful capture. The displayed family has more variation in opening heads, grouped bays, frontage and roof details, but still has similar rectangular masonry masses and restrained ornament. These are bounded demo choices, not verified historical evidence, and they are not a street-readiness or user-approval claim. Grouped arches, richer bay rhythms, massing, storefronts and material interaction remain open.

Verification at initial review: focused composition, authored-group/pinned-lock and family source tests, typecheck, lint, build, standard E2E and both renderer workflows passed; the full suite was running. The build retains its large-chunk warning.
