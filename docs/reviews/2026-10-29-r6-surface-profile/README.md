# R6.P4.1 — surface-preparation discriminator

Using the same accepted six-building source and workflow as the [local baseline](../2026-10-29-r6-local-performance/README.md), temporary Vite instrumentation divided surface preparation into metadata ownership, semantic binding, finish composition and resource creation. Both [WebGPU](webgpu-surface.json) and [WebGL](webgl-surface.json) show approximately 218–266 ms in finish composition per member in the sampled calls; metadata, binding and resource creation were each a few milliseconds. All three saved family files in each instrumented run were byte-identical to the uninstrumented baseline. This is a source-output check, not native pixel equivalence.

Further tile instrumentation separated atlas hashing from pixel blending. Across the last 18 sampled tile calls, the median atlas-hash time was 20.4 ms on WebGPU and 20.3 ms on WebGL; median pixel work was 50.4 ms and 47.3 ms respectively. See the full [WebGPU](webgpu-tile.json) and [WebGL](webgl-tile.json) traces for ranges and other stages. Timings are local wall-clock observations, not GPU frame time or representative-machine results.

A separate [recipe-key trace](webgpu-keys.json) found three distinct existing resolved recipe keys across the six reviewed members: each member used all three. The current compositor validates the owned atlas and member-specific binding artifact and returns a tile with member-specific geometry and binding references. A safe optimization can investigate reusing only verified pixel work within a single family preparation, while separately validating every member binding and preserving its own provenance. An atlas content hash alone does not include the manifest, so any cross-member key must also cover manifest and base-appearance identity. Reusing a whole tile artifact from a different member would carry the wrong binding identity.

The [diagnostic script](verify.mjs) uses temporary source transforms and compares saved output bytes to the local baseline; it requires the local saved family and Chromium. It changes no product behavior. Pixel output, stale or altered atlas bytes, local finish overrides, cancellation, disposal and actual before/after performance remain mandatory checks for the implementation packet.
