# R3.P7 owned IndexedDB writes and transaction acknowledgement

Root reviewed the complete three-path delta against the frozen accepted P6 source. Independent adversarial review read the coherent held production/test files and reported no blocker. Exactly the adapter, its unit tests and the App's IndexedDB fake block change. Every other 250 source file remains literal, including production App/Hall/CSS, source/controller/compiler/materials and the full E2E script.

The adapter changes only put. It structured-clones the complete entry and derives the stored key from that owned copy before its first await. A caller can therefore mutate key fields, dependencies, nested metadata and typed bytes while database opening is held without changing the eventual record. Caller objects are not frozen. An uncloneable artifact rejects before opening a database or creating a transaction.

After database opening, one synchronous Promise executor creates the readwrite transaction, installs completion/error/abort handlers, obtains the object store and issues put. There is no await inside the active transaction. Only transaction completion fulfills the promise; the write request's success is not treated as a commit. Request and transaction failures prefer their actual errors, with explicit fallback errors for absent native error fields. Synchronous transaction/objectStore/put failure rejects the same promise first, then attempts to abort its own transaction. Abort cleanup cannot replace the original error. No detached request promise or separate unobserved transaction promise can reject later.

Readonly get/list methods, parsing, sorted list order, cache-key function, default database/store/version, API declarations and existing helpers remain byte-literal. This packet adds no checkpoint format, delete/close API, upgrade policy, write queue or cross-tab compare-and-swap. The controller's current best-effort persistence policy also remains literal; a storage failure is not newly made into a scene rollback.

The generic fake stages records until commit and clears staged replacements on abort/error. Open, request success, commit and failure phases can be driven independently. It no longer announces constructor-time completion. Six new logical cases prove deferred-open ownership (including typed view offset/bytes and caller mutability), request success remaining pending, independent transaction acknowledgements, late abort/error with native/fallback messages and the previous record retained, request failure before abort, all three synchronous throw stages with throwing abort cleanup/late events, and clone failure before any IO. The deliberately independent completion events test promise isolation; they are not a claim that real same-store readwrite transactions can commit in arbitrary order.

The App fake adds a real transaction lifecycle around its writes. It stages cloned records, emits request success before transaction completion and clears staged work on abort. The entire file outside that fake block remains literal, including imports, every historical test/hook body and every helper function. The original two generic assertions and cachedEntry helper remain literal as well.

Final verification reruns TypeScript, focused adapter/App coverage, both protected browser workflows, the full regression suite, lint and build on one held source. The browser proof includes global structural runs, portable Open, native selection/orbit and the actual selected-window narrow/increase/Save/fresh-page Open/Restore loop. Existing assertions and runtime-validated receipt schemas are unchanged. All five material channels and source/IR/gallery invariants remain in that executed proof.

No new UI capture or detector pass is necessary: production UI/renderer bytes are protected P6 source. Its inspected desktop/compact captures and emitted-JavaScript equivalence record remain inherited, with source pins, rather than being presented as new captures. Four portable legacy canaries and their P5 codec roundtrips are also inherited with unchanged codec and pinned bytes.

Transaction completion acknowledges the IndexedDB transaction; it does not establish an explicit physical-disk flush or crash-proof durability. Automatic editable-source recovery, accepted-publication write ordering, exclusive writer handling, edited-cache replay, undo and representative performance/human appearance remain separate gates.
