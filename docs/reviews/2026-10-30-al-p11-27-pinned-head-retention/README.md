# AL.P11.27 — retain a pinned upper head

Workbench generation preserves a valid imported upper-head pin. When preservation is enabled, a conflicting authored head causes generation to stop without changing the current building. When authored choices are explicitly released, the imported pin remains authoritative. In the isolated signed-storefront family study, roof and massing may vary while a head pin stays fixed; head variation that conflicts with the pin is rejected. The graph, storefront and material input identity are retained.

The [textured render](family.png) uses a demo family-scoped round-head pin across six generated members. It demonstrates the constraint rather than historical evidence or street-ready diversity. The pin still requires an explicit source and lineage; this does not establish metagrinder/UTDG mapping, a new editor control, saved-family integration or historical coverage.

Typecheck, lint and build passed on the final change. The full suite (2,118 tests in 179 files) and browser smoke passed before the final opening-lock conflict guard; the focused family regression passed again afterward, including that guard. The build retains its existing chunk-size warning.
