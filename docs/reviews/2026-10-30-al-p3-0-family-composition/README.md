# AL.P3.0 — explicit family composition policy

This packet adds an owned, versioned composition request and replay-checked plan. The artist-facing integration will opt into variation in openings, frontage and/or roof; unselected groups are represented as explicit keep values. An opening lock conflicts with requested opening or frontage variation and returns a diagnostic. Applying a member's recorded choices uses the existing graph migrations for round heads, sash layouts, storefronts, cornices and parapets, preserving document identity and local opening targets.

The current `commercial-demo-compositions-v1` catalog is six deliberately bounded combinations, not historical evidence or an open-ended style generator. The semantic family seed rotates their assignment to the six member ordinals. The policy must be exposed and persisted in AL.P3.1; the current app and its default family behavior are unchanged. Imported per-parameter locks and combinations that fail actual geometry admission must be checked during integration, not assumed handled by the request's single opening-lock flag. No material or provider path changes.

The final focused run passed 10 tests across the new composition suite and existing family generation suite; typecheck and lint passed. The composition suite verifies deterministic JSON replay, altered-seed ordering, six distinct executed geometry-buffer results, local target preservation, locked/unvaried categories, invalid input, ownership and tamper rejection. This is compiler evidence, not a rendered family or user-facing variation claim.
