# AL.P5.1: grouped-bay geometry

The versioned `construction-grouped-geometry-request` owns a building graph and explicit grouped-bay plans. The compiler partitions each selected front upper bay into non-overlapping child wall scopes, cuts the planned apertures through the continuous wall and builds an existing parametric frame, glazing and trim for each. Each member has a distinct semantic path and instance transform. The complete request, including plans, determines `sourceGraphHash` for this experimental compiler path. A request and its returned source are required for replay; the returned graph alone is not the full source.

Tests inspect actual wall triangles for empty openings and solid masonry piers for both two- and three-member groups. They also check member frame/glass/trim paths and transforms, source replay, unchanged legacy compilation, material-slot bindings, stable identities across a group width edit, an unaffected neighbor and rejection of ambiguous local-width edits, absent walls, mismatched plans and duplicate scopes. Round-headed groups are explicitly rejected. Geometry is generated by the existing wall and window procedures, not preassembled meshes.

The isolated WebGL clay harness shows the [single opening](single-clay.png) and the [two-opening group](grouped-clay.png). The first attempt exposed overlapping sill and lintel trim at a 0.16 m pier; the compiler now requires more than 0.2 m between openings and more than 0.12 m outer masonry when using the existing individual trim, and the shown group uses a 0.24 m pier. These are untextured compiler renders, not product or historical verification. The narrow separation remains visually understated, and material interactions require the app review. [Harness](render-clay.mjs).

This is a compiler API: there is no saved-graph or worker protocol, app control, family integration, or visual acceptance yet. Existing editable local-width targets identify a whole bay, so the compiler rejects them when they address a grouped bay instead of guessing a member. P5.2–P5.4 cover source persistence, artist controls, family integration and renderer review. No historical claim or measured proportions are implied.

Verification: all 2,021 tests across 145 files passed, including 23 focused planning, geometry and round-head regression tests. Typecheck, lint, build and browser E2E smoke passed. The build retains its existing large-chunk warning. One earlier smoke run failed its selection-marker check while the compiler was being edited; the settled-code rerun passed.
