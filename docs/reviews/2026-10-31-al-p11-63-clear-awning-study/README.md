# Separated additional awnings: source-aware study

This isolated demonstration takes an explicit additional-awning count and uses the family seed and member identity to choose among feasible bays. New canopies avoid the entrance, authored awnings and bays immediately adjacent to authored or other new awnings. They copy the authored canopy's dimensions; the original sign, awning, support rods and clearance remain untouched. An infeasible requested count is rejected rather than silently reduced. The source-aware wrapper validates lineage, existing supported pins, and conservative awning/frontage lock paths; it does not establish that the current resolver can ingest every future lock path.

The sample explicitly alternates zero and one additional canopy across six members. It uses grouped windows, some round-headed, plus demo uncovered entrance placement. Counts are supplied for the study, not yet generated by a family policy. `awning-detail.png` and `awning-angle.png` show the separated version. The initial `rejected-adjacent-angle.png` shows adjacent canopies crowding each other at different heights; the revised study avoids that arrangement. The added canopy does not receive support rods automatically, and the separated signed and unsigned canopies still sit at different heights, so this is awaiting visual review rather than an accepted baseline. It is not historical evidence, a saved-family feature, an artist control or a finished street.

The focused test checks deterministic selection, source and support retention, actual canopy geometry, separated bays, opening lock, invalid fit, source identity and a supported captured pin. Reproduce the actual WebGL renders with `node docs/reviews/2026-10-31-al-p11-63-clear-awning-study/render.mjs`.
